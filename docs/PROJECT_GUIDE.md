# InsightFlow Clinical 项目总纲

## 1. 项目到底在做什么

InsightFlow Clinical 是 Clinical Autonomous Investigation Runtime（临床自主调查运行时）。它不是让 LLM（大模型）自由写 SQL，而是把用户问题编译成受治理的调查任务，由模型选择参数化工具，数据库计算事实，系统记录来源、查询动作、数据限制与 Evidence Chain（证据链）。

当前系统支持五个相互隔离的 Investigation Space（调查空间）：

1. 受试者级临床试验分析：比较疗效、安全性、缺失、暴露和研究中心质量。
2. ClinicalTrials.gov 研究注册库：查疾病、药物、器械、行为干预、阶段、招募、申办方和预设终点。
3. openFDA Drug Label（药品标签）：查适应证、给药途径、禁忌、黑框警告和标签不良反应。
4. openFDA FAERS（药品不良事件自发报告）：查药物与不良反应在报告中的共现信号。
5. Synthea synthetic EHR（合成电子健康记录）：验证疾病、用药、就诊、操作和检验观察的队列查询。

| --- | --- | ---: | --- | --- | --- |

| openFDA FAERS | 真实去标识化自发报告 | 50,000 份报告；387,626 条规范化记录 | 2020–2024 分段样本中的药品及报告反应 | 当前样本内药物和反应的共现 | 因果、发生率、药物风险排名 |
| openFDA Drug Label | 真实公开监管文本 | 10,000 份标签 | 具体产品的适应证、生产商、途径、禁忌、警告和不良反应 | 标签写了什么 | 真实疗效、个体用药建议 |
| Synthea | 合成数据 | 108 名虚拟患者；102,808 条已注册记录（其中 5,571 条就诊、3,517 条疾病、3,850 条用药） | 疾病、药物、就诊、操作、观察、器械、免疫、影像等 | 验证 EHR 查询和跨域工具 | 真实人群医学结论 |
| 受试者级临床试验夹具 | 本地可复现合成数据 | 3,000 名受试者；6,000 条 Week-4/Week-12 结局；36,000 条给药记录 | 治疗组/对照组、地区、中心、疗效、缺失、依从性和质量异常 | 验证受试者级调查链和大样本下钻 | 真实患者疗效或医学结论 |

另有 6 个 Synthea 文件仍为 custom candidate（自定义候选域）：claims、claims_transactions、organizations、payer_transitions、payers、providers。系统没有把它们强行映射到错误数据域。

受试者级试验夹具当前已从原来的 50 例扩展到 3,000 例。除刻意保留的 `SITE-18/control` 小格子外，常用中心/治疗组格子均达到小样本阈值，可用于观察真实的均值差异、缺失率和依从性下钻；它是测试夹具，不是公开真实患者数据。

## 3. 一次调查如何运行

```text
用户问题
  → 选择或识别调查空间
  → Question Compiler（问题编译器）确定意图与候选能力
  → LLM 在受治理工具目录中选择调查入口并规范检索主题
  → 系统选择受治理调查方法
  → 连续执行多项参数化只读查询
  → 分来源形成结构化观测与人类可读解释
  → 数据来源限制和反证检查
  → 引用 Evidence ID 的结论
  → 临床结论进入人工审批边界
```

DeepSeek、Claude、OpenAI、GLM、Kimi 和自定义兼容模型只负责决策，不接收数据库写权限，也不能扩展工具白名单。当前已实测 DeepSeek 能把 FAERS 问题路由到 `lookup_faers_signals`，数据库随后计算报告共现。

## 5. 开源项目借鉴与重构原则

- 借鉴 MCP BioForensics：在研究注册空间增加结构化过滤 + 医学语义检索；不复制其仍在规划中的取证报告。
- 借鉴 OHDSI Nostos：建立医学词语到标准概念、同义词和层级后代的 Concept Resolver（概念解析器）。
- 借鉴 QwenPaw-Data：将 Facts（事实）、Methodology（分析方法）、Execution（执行）拆成独立契约。
- 借鉴 Agentic Analytics：每条证据记录 source fingerprint、输入参数、执行版本和结果摘要，使调查可重放。
- 不采用自由 Text-to-SQL 作为主路径；不把所有临床来源混成一个 RAG 文档库。

## 6. 下一阶段重构规划

### Task 11：多步公共调查与 DeepSeek 实机验收（已完成）

- 研究筛选：查找匹配研究，再按阶段、研究类型、招募状态与平均样本规模比较设计。
- 药品安全核对：分别查询 FAERS、FDA 标签和相关注册研究，三类证据保持隔离并共同出现在结论中。
- 合成病历画像：先统计匹配患者及记录数量，再汇总常见疾病、用药、操作和观察。
- DeepSeek 选择调查入口并规范实体，受治理方法决定后续允许执行的工具。真实验收中，模型将中文主题规范为 `METFORMIN`，系统连续形成 3 条独立证据。
- 前端新增“调查过程”，用中文展示每一步查了什么及形成了哪条证据。

### Task 12：动态数据目录与工具能力缺口探索（V15 已完成目录部分）

- 不把“工具达到 100 个”当作完成标准；先按真实问题覆盖率、正确选择率和证据质量判断缺口。
- 建立药品安全、研究设计、临床试验、实验室检查、患者时间线、队列比较、影像、费用等 Capability Pack（能力包）。
- 每个问题只向模型开放与当前数据域相关的 5–15 个工具，避免上百工具同时出现导致误选。
- 记录无法回答的问题、缺失数据域、缺失操作和人工期望证据，形成可排序的 Tool Gap Backlog（工具缺口清单）。
- 每批新增工具都必须有黄金问题、权限边界、空结果语义和真实数据库验证。

V15 已完成 `GET /api/v15/clinical/catalog` 和前端“数据目录（Data Catalog）”页面。目录只读取分析 schema 与已发布 JSONB 域记录的元数据，自动识别数据集、字段类型、空值比例、字段角色、数据粒度和中文别名；未知域保留为 `custom_candidate（自定义候选）`。调查规划器收到的 `measures / dimensions` 是实际字段经过语义映射后的候选，仍必须通过工具注册表和计划校验器，不能自由生成 SQL。完整说明见 [`V15_DATA_CATALOG.md`](V15_DATA_CATALOG.md)。

V15 已覆盖目录发现以及年龄段、性别、疾病严重度的一维受治理分层。之后优先基于真实失败问题补统计能力，而不是为了“工具数量超过 100”直接堆工具。

## 7. 当前验收方式

V15 的字段级目录可从产品侧边栏“数据目录”打开，或调用 `/api/v15/clinical/catalog` 查看。

启动：

```powershell
docker compose up -d --build
```

浏览器访问 `http://localhost:55173/`，进入动态调查：

- 研究注册：主题 `Metformin`，问题“有哪些 Metformin 相关的临床研究？”
- 药物标签：主题 `Sildenafil`，问题“Sildenafil 的 FDA 标签有哪些警告和禁忌？”
- FAERS：主题 `METFORMIN`，问题“FAERS 中 METFORMIN 最常与哪些不良反应共同报告？”
- 合成 EHR：主题 `diabetes`，问题“合成病历中 diabetes 队列包含多少患者和就诊记录？”
- 试验分析：选择 `TRIAL-CF-101`，问题“治疗组与对照组的 Week-12 结局是否存在差异？”

阅读结论时必须同时检查 Evidence（证据）来源和“不能证明”说明。FAERS 的数字只代表报告共现；ClinicalTrials.gov 只代表研究注册；Synthea 只代表虚拟患者。
